# v0.8 量化实验（固定种子，可复现）

运行：`node scripts/simulate80.cjs`。原始结果：[balance80.json](balance80.json)。

## 内容结构

80 = 16 通用 + 8×5 专属 + 16 桥接 + 8 核心。5 辅助槽 + 1 核心槽。

## 结果及边界

| 指标 | 实测 | 定义／限制 |
|---|---:|---|
| 10 万次引导选牌结构成型 | 98.96% | 8 次奖励后满5辅助、至少3相关含1专属、至少2种角色；不含战斗门槛 |
| 1 万次均匀抽牌对照 | 52.95% | 同样的选牌策略，取消奖励引导和权重 |
| P_build | 80.08% | 2048 个另取种子的获得构筑，结构达标且对 E002 三战至少两胜；目标70% |
| 潜在冲突牌出现率 | 0.51% | 兑金／铸盾互斥；可替换，不等于完全死牌率 |
| C_hybrid | 50.00% | 明确机制边 14/28，见桥接验证测试；目标50% |
| D_effective | 968 | 去除纯数值差异后的机制签名，且过强度门槛；初始目标16 |
| E 抽样估计 | 58.79% | 512 个均匀合法构筑，存在数据库协同边且三战至少两胜；不是全空间枚举 |
| 战斗超时 | 113 | 6144 场中40回合未分胜负 |

P_dead 尚不能直接等同潜在冲突率：依赖牌缺少伙伴属于条件死牌，需要完整获得顺序和玩家适应策略再测。A 核心适配采用可触发的能力兼容口径；最高骰已将优势改为伤害／护盾，各核心不再禁用整个计分阶段。兼容不代表每张牌单独即强，也不保证同套牌在所有核心下同强。

**这些数值不是玩家通关率，也不能证明80为最小最优卡池。** 未虚构40/60/100/120张尚未实现的池。该实验不包含地图战斗损耗、付费商店、方向切换与真人决策。

## 奖励死牌筛查与核心适配实证

对同样10万次固定种子选牌的240万奖励位置，按“当前持有牌缺少必要伙伴，或与已装备牌互斥”筛查，P_dead_screen=10.27%（目标≤15%）；缺伙伴 9.97%，互斥 0.51%，取并集不重复计数。互斥牌可免费替换，因此这项对互斥采取保守口径；缺伙伴不代表之后无法补齐。检测的是明确规则依赖，不等于穷举所有游戏状态的真正不可达性。

核心适配 A 通过合法上下文中的差分计算：加入牌后改变计分、伤害、资源、储存或骰面，才计作有证据的有效用途。允许条件牌搭配伙伴；8张整备／地图／战后牌独立测试。每个组合最多300个种子，没有找到证据的牌不直接判定永久不可用，因此下列是采样下界。
