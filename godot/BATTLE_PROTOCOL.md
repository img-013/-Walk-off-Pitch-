# 赌桌协议 1.0（实验原型）

## 启用与编辑

运行 `scenes/main.tscn`，在设置或战斗右上角打开「赌桌协议 / 调试」。默认关闭；仅在投骰前允许切换，切换清空公共赌注、战术筹码以及先手奖励的剩余护盾。也可以在 Main 根节点 Inspector 打开 `battle_experiment_enabled`。

所有新增战斗参数、敌人赌局池、战术筹码效果及演出强度在 `data/battle_experiment.json`。UI 为 `scenes/ui/BattleHUD.tscn` 内可编辑的节点；演出节点为 Main/SettlementPresenter。未改变摄像机。

## 实际架构和优先级

- `run_state.gd`：投骰、锁骰、提前收手、战术筹码、单次提交、存档。settle 在演出前完整提交；回合编号和阶段防止重复调用。
- `rules_engine.gd`：复制输入后纯计算。原80张卡数据不变，原敌人状态触发记忆仍按旧逻辑处理，不把新演出事件反灌进敌人AI。
- `battle_protocol.gd`：公共赌注、赌局奖励、最低伤害、结构化事件及高潮判定。
- `settlement_presenter.gd`：只读结果快照，不重算分数、不消费随机数、不发资源。正常、快速、跳过最终展示相同结果。

真实顺序：骰面已在投骰时变换 → 核心基础计分 → 优势/转换/敌人场域 → 比较（反向、平局判胜）→ 基础最低伤害 → 原风险修正、护盾与免伤 → 原主动加注 → 依赖伤害的金币/治疗/储存 → 提交。

演出按依赖展示：基础骰面、必要的核心基础换算、有效规则贡献、最终得分、比较、伤害组成、下注/赌注、最终爆发。无法把核心基础换算拖到辅助牌之后，否则中间得分不真实。后置资源效果也不伪装成加分。

## 冲突处理的最小方案

- 真正平局是没有胜者。R006 平局判胜优先兑现赌注，但它的合成伤害值不用于「险胜」有效分差。
- 最低3点是抵盾前基础伤害；旧免伤、护盾仍能使最终伤害为0。原敌人主动加注仍按旧规则生效，没有新增倍率。
- 额外伤害按旧卡 → 赌局奖励 → 公共赌注分配6点预算。敌人兑现时，其已有额外攻击先占预算；不削减已有攻击。赌注即便被封顶削减仍一次清空。
- 先手获胜的2护盾存至下一回合，独立于旧牌3点储存护盾上限；避免获胜回合立即浪费。
- 提前收手保持玩家 roll=2。R016/R017/R049/R069/R076/R079 及投骰函数中第三掷转换不触发。描述「末掷」而非「第三掷」的效果可在第二掷结束时判断。敌人用原高/低点保留策略补完第三掷，不调用玩家第三掷卡牌钩子。
- 战术筹码只修改当前骰值，不改永久六面，不冒充卡牌造成的骰面变化；满6时不可消费。第一版每场战斗从0枚开始。
- 实验开关随Godot v1存档保存；旧v1存档缺字段视为关闭，继续兼容。未升级或改写网页存档。

## 事件契约

每个事件包含 type、source_rule_id、resource、before、delta、after、animate、ui_element、sound、label。额外可有 effective。

resource 区分 score、advantage、shield、bank_shield、bank_adv、gold_generated、heal、die_face、enemy_reroll、damage、verdict 等。产金转储存时明确标注“产金（转为储存优势）”，不会表示钱包获得金币。治疗显示实际可恢复量；额外伤害按上限分配后才展示；最终抵盾/旧修正单独记录。

新增常规卡牌效果通过通用 emit/record 输出即可复用演出，不需要新动画。新的运行阶段效果通过 rollEvents 记录实际变化。

## 演出和音效

每次有效触发有1.12倍卡牌强调、短金色边缘光、轻微摇动及贡献数字；真实计分事件缓动更新分数。筹码下落累积，兑现飞向胜方。仅高潮事件播放短停、桌面震动、局部暗金闪光、核心高亮、伤害放大和敌方后仰，不动摄像机，不全屏闪白。

复用项目 click/reveal 音效，连锁逐步升调。`audio/protocol_impact.wav` 为原创合成占位低频/金属共鸣层，可在 SettlementPresenter 的 trigger_sound、climax_sound、impact_sound 属性替换；没有使用 Balatro 素材。每轮演出时间上限2.5秒，超过后立即收束到权威结果。

## 测试

`Godot --headless --path <项目> --script res://tests/battle_protocol_check.gd`

32项专项断言（含反向、平局判胜、公共赌注双方兑现/上限、提前收手、四赌局、战术资源、重复提交、封顶归因、实际治疗）；另有1072个原版结算对照，零差异。

`Godot --path <项目> --script res://tests/protocol_presentation_check.gd`

实际启动Godot场景：普通胜利、两次平局、连锁、赌局成功/失败、高赌注兑现，以及中途重复点击跳过。17项断言；演出约1.4–2.2秒；测试关闭存档写入，不覆盖玩家远征。调试强制同分及爆发为一次性，并在UI明确标注。

第一版赌局按敌人池确定轮换，不加入新AI。强制同分保留旧平局判胜优先级。调试强制爆发不改变伤害。
